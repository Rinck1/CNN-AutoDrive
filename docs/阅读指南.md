# MiniFlows 代码阅读指南（总纲）

> 适用版本：`main` 分支（含 ViT 版本）
> 代码规模：框架本体约 4,100 行，全项目约 10,500 行（含注释）
> 阅读目标：能跑 → 能懂 → 能改 → 能讲

这套指南由 **1 份总纲 + 34 份单文件指南** 组成，每个代码文件一份。
单文件指南统一按「定位 → 结构速览 → 逐段讲解 → 调用关系 → 易错点 → 自检问题」组织。

## 二、模块依赖关系

```
applications / experiments / pytorch_benchmark / tests
        │
        ├── trainer.py ── utils.py ── data.py
        │        │
        ├── layers.py ── losses.py ── optim.py
        │        │
        ├── transformer.py（依赖 layers + ops）
        │        │
        ├── visualization.py（只读 Node）
        │        │
        └── ops.py ── autodiff.py
                 │
              graph.py
                 │
               numpy
```

依赖原则：**上层只能依赖下层**；`graph.py` 只依赖 numpy；`ops.py` 只依赖 graph；
`layers/losses/optim` 依赖 ops；`trainer/utils/data/visualization` 依赖上述；
应用脚本只调用公开 API。

## 四、每份单文件指南怎么用

每份指南都包含：

1. **文件定位**：这个文件解决什么问题、前置知识、在整个项目中的位置；
2. **结构速览**：按建议阅读顺序列出类/函数、行号、一句话作用；
3. **逐段讲解**：关键代码路径、公式、状态变化；
4. **调用关系**：谁会调用它、它调用谁、数据形状如何流动；
5. **易错点/设计取舍**：为什么这样写、有哪些坑；
6. **自检问题**：能答上来才算读懂。

建议读法：

- **第一遍**：只读「文件定位 + 结构速览」，知道每个文件干什么；
- **第二遍**：跟「逐段讲解」走，同时在纸上画数据形状；
- **第三遍**：回答自检问题，跑对应测试验证；
- **第四遍（可选）**：故意改坏一行，看测试是否能抓住。

## 五、阅读前必须知道的 8 个约定

1. **统一 float64**：核心框架默认 `np.float64`，为了数值梯度检验精度；
   float32 会显著降低检验精度（详见 `guide/02_graph.md`）。
2. **梯度是累加的**：与 PyTorch 相同；每步训练前必须 `optimizer.zero_grad()`，
   否则梯度会跨 batch 叠加。
3. **只有 `requires_grad=True` 的子图参与反向**：常量节点不积累梯度。
4. **所有形状按 batch-first**：图像 `(N,C,H,W)`，序列 `(N,L,D)`，输出 `(N,1)` 或 `(N,C)`。
5. **测试集/验证集要分开**：演示脚本 `donkeycar.py`、`mnist.py`、`iris.py`
   存在“测试集兼作验证集”的简化；严格指标以 `donkeycar_eval.py` 为准。
6. **没有 `no_grad`**：`Trainer.predict/evaluate` 仍会建计算图；推理大 batch 时注意内存。
7. **attention 图不是因果解释**：见 `guide/12_transformer.md` 与 `guide/20_donkeycar_vit.md`。
8. **产物都在 `outputs/`**：脚本可重复运行，会覆盖同名图片/报告；`--quick` 产物带后缀。

## 六、四个通用调试技巧

### 6.1 先跑测试，再读代码

```bash
python tests/test_core.py
python tests/test_infra.py
python tests/test_transformer.py
```

三套测试全绿，说明你本地的 numpy/环境没问题；读代码时可以把测试当“可执行规格”。

### 6.2 用极小形状手推

遇到形状不确定，先写：

```python
import numpy as np
from miniflows.graph import Node
from miniflows import ops
x = Node(np.random.randn(2, 3, 8, 8))
print(ops.conv2d(x, Node(np.random.randn(4, 3, 3, 3)),
                 stride=1, padding=1).shape)   # (2,4,8,8)
```

### 6.3 梯度不对，先查广播

本项目管理反复出现的 bug 都是广播：

- `(N,1)` 预测与 `(N,)` 标签 → `(N,N)`；
- `(F,)` 偏置对 3D 序列 `(N,L,D)` → 对齐错维；
- `np.ndarray - Node` → object 数组。

读 `guide/03_ops.md` 的 `unbroadcast` 与 `guide/05_losses.md` 的形状对齐。

### 6.4 性能问题先 profile

```bash
python -m cProfile -s cumtime applications/mnist.py
```

不要凭感觉优化；先确认瓶颈是卷积、LayerNorm 还是 Python 调度。

## 八、建议的练习（从易到难）

1. 给 `Linear` 增加 `bias=False` 选项，并补测试；
2. 实现 `BatchNorm2D`（训练/评估两套统计量），在 MNIST 上对比收敛；
3. 给 `MSELoss` 增加 `reduction='sum'`，验证梯度尺度变化；
4. 把 `Dropout` 的 `p` 做成可调度（训练后期减小）；
5. 给 `ops.softmax` 增加 `mask` 参数，实现 causal mask；
6. 实现 `Embedding` 层（gather 反向 scatter-add），做一个字符级分类；
7. 给 `Trainer` 加 `no_grad` 推理路径，测内存与速度；
8. 用 `pybind11` 把 `conv2d` 前向/反向移到 C++，与 numpy 版本对拍。
