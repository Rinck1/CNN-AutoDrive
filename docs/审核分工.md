## 一、审核目标与工作纪律

### 1.1 审核要回答的五个问题

1. **能跑**：在干净克隆的仓库里，按 README 命令能跑通吗？
2. **算对**：梯度、卷积、损失、优化器的数值是否正确？
3. **可复现**：固定种子后指标能否重复？文档里的数字与实测一致吗？
4. **注释达标**：是否做到"模块头 + 类/函数 docstring + 关键行"全中文注释？
5. **交付完整**：产物、文档、Git 仓库是否齐全、干净、可提交？

### 1.2 纪律

- 审核员**只提问题、不改代码**；修复由原作者完成，审核员复验。
- 所有问题必须附：位置（`file:line`）、复现命令、期望/实际、日志或截图。
- 每人的结论写入 `docs/审核记录.md`（模板见第七节），并在 PR/Issue 中留痕。
- 建议在 GitHub 上开 Issue，标签：`review/S1`、`review/S2`、`review/S3`。
- 审核期间不合并未经配对复核的修改。

### 1.3 建议的干净环境做法

```bash

cd review-<姓名>
python -m venv .venv
```

## 三、每人详细任务卡

### 审核员 A：框架数学核心

**范围**：`miniflows/graph.py`、`miniflows/ops.py`、`experiments/exp1_graph_viz.py`

**必跑命令**

```bash
python tests/test_core.py          # 重点看测试1/2/3/5
python experiments/exp1_graph_viz.py
```

**必查点**

1. **反向传播手算对照**：
   - `z=(a+b)*(b+c)`，a=2,b=3,c=1 时 `dz/da=4, dz/db=9, dz/dc=5`；
   - `y=x*x+x` 对 x 的梯度是否为 `2x+1`（验证 `+=` 累加而非覆盖）。
2. **运算符与广播**：
   - `Node - np.ndarray`、`np.ndarray - Node`、标量混合运算是否都返回 `Node`；
   - 检查 `__array_priority__ = 1000` 是否真的被设置；
   - `unbroadcast` 对 `(N,C,H,W)` 与 `(F,)`、`(1,F,1,1)`、`(1,F)` 的还原是否正确。
3. **卷积**：
   - 抽查 `stride/padding` 组合，与脚本内朴素 conv 对拍；
   - `im2col → col2im` 是否严格往返（可写临时脚本验证，允许临时文件但不入库）；
   - 非整除尺寸（如 H=7, K=3, S=2）输出形状是否按向下取整；
   - 反向时重叠窗口的梯度是否累加。
4. **池化**：
   - `maxpool2d` 反向是否只路由到最大值位置；并列最大值是否按注释约定处理；
   - `avgpool2d` 反向是否为 `g/(kh*kw)`。
5. **激活**：ReLU 在 0 点的约定；Sigmoid 数值稳定；Softmax 沿指定轴归一。
6. **图工具**：`build_topo` 拓扑序合法、`collect_edges` 边数正确、常量节点无梯度、`detach` 断图。
7. **性能**：记录 `test_core` 总耗时、MNIST 单轮耗时（可选跑 `python applications/mnist.py`，约 11 s），判断 im2col 是否真正生效。
8. **扩展①**：
   - 两张 PNG 尺寸是否合理（期望约 994×706、1837×967，文件 <1 MB）；
   - 节点框文字是否清楚、箭头方向是否为父→子、图例是否正确；
   - `max_nodes` 截断逻辑是否只保留离输出最近的节点。
9. **注释抽查**：随机抽 10 个类/函数，是否都有完整中文 docstring（功能/参数/返回/思路）。

**重点怀疑项（请主动构造反例）**

- 卷积 `padding` 大于核尺寸、`stride` 大于核尺寸；
- 1×1 卷积、C=1、N=1、非方形输入；
- maxpool 窗口有并列最大值时的梯度总和是否符合约定；
- 连续两次 `backward()` 不清梯度是否累加（语义应与 PyTorch 一致）。

### 审核员 B：自动求导与模型组件

**范围**：`miniflows/autodiff.py`、`miniflows/layers.py`、`miniflows/losses.py`、`tests/test_core.py`

**必跑命令**

```bash
python tests/test_core.py
python tests/test_transformer.py     # ViT 新算子/LayerNorm/注意力/全参数梯度
python - <<'PY'
# 允许在临时文件中写验证脚本，不要提交
PY
```

**必查点**

1. **梯度检验工具本身是否可信**：
   - 中心差分公式、`eps=1e-5`、相对误差分母 `max(1e-8, |a|+|n|)`；
   - 输入统一 float64；`gradient_check` 是否真的对每个输入分别扰动；
   - 构造一个已知错误的反向（如 `x*2` 反向写成 `g*3`），确认工具会报失败。
2. **损失函数**：
   - `MSELoss` 的 `mean` 维度、反向 `2(pred-y)/N`；
   - `BCEWithLogitsLoss` 在 z=±100 时是否有限；`(N,1)` 与 `(N,)` 组合是否不再广播成 `(N,N)`（本问题已修，需回归）；
   - `CrossEntropyLoss` 在 logits 很大（如 1e3）时是否稳定；反向是否为 `(softmax-onehot)/N`；
   - `l2_penalty` 只对 W 还是也对 b 生效？是否与文档一致。
3. **层接口**：
   - `Linear` 的 W 形状是 `(in,out)` 还是 `(out,in)`；He/Xavier 的 std 是否与注释公式一致；
   - `Conv2D` 参数形状 `(F,C,KH,KW)`、偏置零初始化；
   - `Dropout` 训练态是否 `mask/(1-p)`（inverted）、评估态恒等；
   - `Sequential.named_params()` 命名是否唯一、`train_mode` 是否递归、`summary` 参数量是否与手算一致；
   - 无参数层的 `params()` 是否返回空列表。
4. **测试质量**：
   - `tests/test_core.py` 的断言是否可能"永真"（例如只比较形状不比较数值）；
   - 34 项梯度检验是否相互独立；随机输入是否避开 ReLU 0 点、maxpool 平局；
   - 测试是否受执行顺序影响（单独运行某一测试是否也通过）。
5. **文档一致性**：`docs/API契约.md` §5-7 的签名、返回形状、默认参数是否与代码一致。
6. **注释抽查**：上述文件随机 10 个函数，docstring 是否讲清数学公式与反向推导。
7. **ViT 组件（新增）**：
   - `LayerNorm` 用算子组合实现，检查 `(N,L,D)` 的均值/方差是否沿最后一维；
   - `MultiHeadSelfAttention` 的 Q/K/V 拆头、缩放 `1/√Dh`、softmax 轴、合并头是否正确；
   - `concat/broadcast_to/select/gelu` 的反向是否与中心差分一致（`test_transformer.py`）；
   - 极小 ViT 全参数梯度 max_rel 是否 <1e-5；`[CLS]` 注意力形状是否为 `(N,H,L+1,L+1)`；
   - `broadcast_add` 对 3D 序列 `(N,L,D)` 的偏置是否对齐最后一维（此前 4D 规则会错）。

**重点怀疑项**

- BCE/CE 的 target 形状陷阱（`(N,)` vs `(N,1)`）；
- `Linear(init='normal', init_std=...)` 的 std 是标准差还是方差；
- `Softmax(axis=...)` 与损失内部 softmax 是否重复；
- `summary()` 在输入形状为 `(1,28,28)` 时是否按 batch=1 推断。

### 审核员 C：训练/优化/可视化

**范围**：`miniflows/optim.py`、`miniflows/trainer.py`、`miniflows/utils.py`、
`miniflows/visualization.py`、`experiments/exp5_optimizations.py`

**必跑命令**

```bash
python experiments/exp5_optimizations.py
python tests/test_infra.py          # 其中 3 项属于本范围
```

**必查点**

1. **优化器**：
   - Adam 第一步更新量是否约等于 `lr·sign(g)`（偏差修正是否正确）；
   - `m/v` 形状与参数一致、`t` 每步递增、`eps` 是否加在分母；
   - MBGD 动量公式是否为 `v=μv+g; θ-=lr·v`；
   - `step()` 是否只改 `p.data`、不建图；`zero_grad()` 是否清空全部参数。
2. **训练器**：
   - 最后一个不满 batch 是否被处理（不能丢样本）；
   - `shuffle` 是否受 `Trainer(seed=...)` 控制、两次训练是否可复现；
   - `callbacks` 返回值语义（True 早停）、`l2_fn` 是否每个 batch 都加；
   - 训练前 `train_mode(True)`、验证前 `False` 是否确实执行；
   - `evaluate` 的单输出阈值是否为 0（logits）、多分类是否 argmax、回归是否 MSE；
   - `predict/predict_classes` 是否与 `evaluate` 口径一致。
3. **工具**：
   - `EarlyStopping` 的 `min_delta`/`patience` 边界（恰好等于阈值时是否算改善）；
   - `LRScheduler` step/plateau 两种模式的 lr 轨迹是否与 exp5 打印一致；
   - `save_model/load_model` 是否按参数名匹配；参数名不一致时是否报错而不是静默错位；
   - `count_params` 是否只统计可训练参数。
4. **可视化**：
   - 所有图是否 `savefig` 后 `close`，没有 `plt.show()`；
   - `plot_loss_curve` 的 loss 左轴、acc 右轴是否正确；
   - `draw_computation_graph` 的坐标轴范围是否显式设置（此前修复过 PNG 上万像素的问题，需回归）；
   - `plot_images_grid` 的标题是否用 `set_title`（`axis('off')` 会隐藏 xlabel）；
   - 抽查 3 张图的文件大小与分辨率是否合理。
5. **exp5 结论**：
   - 优化器对比是否同数据同初始化；Dropout 对照是否只差 Dropout；
   - 早停演示的最优轮次/停止轮次是否与打印一致；
   - 保存/加载的 `max_diff` 是否为 0；
   - `outputs/exp5/优化功能演示结论.md` 的数字是否与运行输出一致。

**重点怀疑项**

- 连续训练多个 epoch 后计算图是否持续增长（内存泄漏）；
- `batch_size > N`、`epochs=0`、验证集为空等边界；
- 学习率被调度器改成 0 或负数的保护；
- 图表中文字体是否在另一台机器上仍正常（Linux 需装字体）。
